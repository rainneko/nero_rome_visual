# Token 账本：罗马是怎么一个 token 一个 token 建起来的

**数据来源：** Claude Code 会话记录里每一次模型调用的 `usage`（按消息 id 去重后求和）。
重新生成：`python3 novel2city/scripts/token_ledger.py <会话.jsonl> "nero-rome-reader /docs/making-of/data"`（脚本在 skill 里，谁都能用来量自己的花费）。
生成结果：每个 agent 一行的 `data/agents.csv`，以及按每次新指令切段的 `data/phases.csv`。

**范围：**
* 实测部分：2026-10-21 09:34 – 10-23 09:10，同一个会话，含 1 个主控和 43 个子代理。
* 第一天的版本（10-19，单文件，`novel2city/examples/rome-day1.html`）在另一个对话里完成，没有记录。
  作者的估计是 **1–2 个 5 小时额度**。
* 10-19 到 10-21 之间拆仓库、加安齐奥初版等迭代也不在本账本里。
* 作者按订阅额度估算，总花费大约 **2 个周额度**。

**两个数怎么读：**
* **处理量**：模型实际读写的全部 token，包括缓存读取。
* **新 token**：缓存写入 + 未缓存输入 + 输出。
* 缓存读取的单价只是正常输入的一小部分，所以**新 token 更接近花费**。
* 处理量反映的是"上下文有多长 × 调用多少次"。

## 5. 账本说明了什么（博客、视频的论据）
1. **续用 vs 新开：**
   * 同一个 Sonnet 续用 6 段，平均**每次调用读 57.5 万 token**。
   * 每段新开的 Sonnet 平均**每次调用读 22 万 token**，约便宜 2.6 倍，而且每段完成的任务更多。
2. **轮数决定成本。**
   * 一次过的资产只要 2–3 M。
   * 改 4–5 轮又续用的资产要 25–36 M，相差 10 倍以上。
3. **试验要先量化。**
   * AO 烘焙花了 31 M，结论是不用。
   * img2threejs 对比花了 35 M，只做到第一阶段。
   * 同题的 Blender 流程只要 1.1 M。
4. **主控的大头是长上下文。**
   * 安齐奥那天主控上下文涨到 96 万，146 M 处理量里只有 3.4 M 是新 token。
   * 早点压缩对话、把审图交给拼图，比少看图更省。
5. **估算偏差。** 第 15 篇复盘（`novel2city/references/15-token-cost.md`）当时是用"调用次数 × 平均上下文"估的：
   * Haiku 估了 530 M，实测 432 M。
   * Sonnet 估了 180 M，实测 384 M。Sonnet 被低估了一半多：截图读入和 70 万级的上下文都比想象的贵。

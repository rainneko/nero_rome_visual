# 搬到 Unity、做街上的人、上 Steam：要做什么（2026-11-11）

代码事实来自一次只读的清点（没有构建）。Steam 和 Unity 的条款来自官方页面，11-11 抓取。法律和税务的部分不是法律意见。

## 0. 先说结论

1. **不要把生成器重写成 C#。** 让现在的 JavaScript 生成器继续当唯一的源头，加一个导出步骤，Unity 只负责显示、走路、人物和发行。
2. **最大的一块工作不是模型，是外观。** 这个项目没有贴图文件，墙、窗、瓦、地面全是着色器按顶点属性画出来的。搬过去等于把这套着色器重写一遍。
3. **第二大的一块是地面视角。** 现在的城市只为俯瞰做过。人站在街上看，门、店面、路面、人物都要补。只能先做一个街区。
4. **先花两周做试验再决定。** 如果目标只是"上 Steam"，把现有网页包一层壳两三周就能发。Unity 值得做的前提是你确实要会走路的人和街道视角。

## 1. 现在有什么，缺什么

| 方面 | 现状 | 对 Unity 意味着什么 |
|---|---|---|
| 规模 | 源码约 8000 行（很多是超长行），1.6 MB。桌面档全城约 4400 万三角形，约 2.6 万栋房子 | 不能整城原样搬，要分块和做远近简化 |
| 生成 | 地形、路、房子、树、人群都在浏览器里现场生成。随机数按地点取种子，结果可重复 | 可以在无界面的浏览器里跑生成器再导出 |
| 外观 | 没有贴图文件。`MAT.city` 一个着色器按每个顶点的三组属性画墙、窗、瓦、做旧。GLB 模型也只带材质名，图案由页面画 | 着色器要移植；导出要带上这三组顶点属性 |
| 模型 | 85 个 GLB 在用，约 69 MB，没有远近简化 | 可以直接导入 |
| 地形 | 解析函数，采样成约 12 m 的网格，四处有 3 m 的细块 | 导出成网格，不用 Unity 自带的地形 |
| 街道数据 | 主干道是折线数组。街坊数据要靠切分代码重放才能展开 | 导出时要把展开后的街道中线和街坊多边形写出来 |
| 人 | 一个 72 三角形的静态锥体，没有朝向、动作、寻路 | 全部新做 |
| 镜头 | 只有环绕镜头，最低 14 m，没有碰撞和点选 | 全部新做 |
| 界面 | 全是网页元素 | 全部重做 |
| 故事 | 9 个状态、约 93 个图层、约 160 个地点标签、10 条段落触发、62 条地名链接 | 都是数据，可以导出 |
| 帧率 | 每帧 1500 到 2200 万三角形，M1 Pro 上 36 到 49 毫秒 | 游戏要 60 帧，每帧要压到三五百万以内 |
| 安齐奥和奥斯提亚 | 画在 7 万米和 8 万米以外 | Unity 用单精度，离原点这么远会抖。要拆成独立场景 |

## 2. 三条路

| 路 | 做法 | 多久能上 Steam | 得到什么 | 得不到什么 |
|---|---|---|---|---|
| 甲：网页包壳 | 用 Electron 或 Tauri 包现有页面，接 Steam 的接口 | 两三周 | 现在的阅读器原样上架 | 走路、人物、手柄、Steam Deck 上的表现都受限 |
| 乙：网页里加步行和人 | 在 three.js 里做低机位、碰撞、实例化的动画人群 | 两三个月 | 一套代码；网页版同时受益 | 动画、寻路、性能工具都要自己造；最后还得走甲才能上架 |
| 丙：Unity 做第二个前端 | 生成器导出，Unity 显示 | 竖切片两三个月，能卖的版本半年以上 | 人物、动画、寻路、手柄、多平台的成熟工具 | 着色器要重写；多维护一套 |

建议走丙，同时把甲当保底：试验期顺手把壳包好，哪天丙做不下去，甲随时能发。网页版继续留着，它是论文的展示品，也是免费试玩。

## 3. 路线

### U0 试验，两周，过了才往下走

做一件最小的事：导出广场到苏布拉边缘约 400 m 见方、状态 0 的一块，在 Unity 里走一圈，街上放 200 个会走的人。

量三样：中档显卡上的帧率；着色器移植一个下午能搬多少；街上看缺什么。

过关条件：60 帧；墙和瓦看起来和网页是同一座城；列得出地面视角的缺项清单并且做得完。任何一条不成立，就退回路甲。

### U1 导出管线，四到六周

- 在 `tools/export/` 下写导出脚本，用仓库里已有的无界面浏览器跑生成器。
- **城市几何用自己的二进制格式，不用 glTF。** 原因：外观靠每顶点三组四维属性，glTF 的纹理坐标只有二维，塞进去要拆六组。自己的格式是位置、法线、索引加三组属性的原始数组，配一个 JSON 说明。Unity 端写一个导入器，把属性放进网格的 UV 通道。
- 按 400 m 的格子分块，每块按图层分开，文件名里带图层名和状态范围。
- GLB 模型原样导入，另出一张表：材质名对应 Unity 的哪个材质。
- 同时导出四份数据：地形网格；街道中线图（节点、边、宽度、是不是台阶）；街坊多边形；故事数据（状态、图层范围、地点、镜头、触发句）。
- 每栋建筑带稳定编号。**这个编号和论文里的"构件登记表"是同一个东西**，一次做好两边都用。

### U2 外观，四到六周

- 用 URP，不用 HDRP。风格化的低面数画面不需要 HDRP，URP 的硬件覆盖更宽，Steam Deck 也跑得动。
- 把 `MAT.city`（墙、窗、瓦、烟熏做旧）、地形、水、树叶、天空逐个从 GLSL 移植到 HLSL。这是机械活，适合 agent 做。验收方法照搬现在的流程：同一机位，网页一张、Unity 一张，并排比。
- 后处理：泛光、调色、平涂滤镜、晶格滤镜，做成全屏通道。
- 性能：每块做合并的远景简化版；树在远处换成面片；打开 Unity 6 的 GPU 遮挡剔除。街道视角下房子互相遮挡，剔除的收益很大。

### U3 人，六到八周

| 部分 | 做法 |
|---|---|
| 身体 | 从 Blender 官方的 CC0 人体基础网格出发（巨人像重做时已经用过）。近景 2000 三角形左右，中景 600 |
| 衣服 | 8 到 10 种原型：短袍的平民、托加、妇女的长衣和披肩、奴隶、士兵、小贩、孩子。颜色用调色板贴图换 |
| 动作 | 走、站、交谈、扛东西、坐。优先用 CC0 的动作库，省掉授权上的麻烦 |
| 成群显示 | 把动作烘成顶点动画贴图，用 GPU 实例化画。目标是同屏 2000 人 |
| 走路 | 人群沿导出的街道图走，靠右、分道，不用导航网格。只有玩家自己用碰撞体 |
| 行为 | 按时辰和状态定密度；酒铺、水池、面包房当吸引点；段落触发时人群有反应。依据从庞贝的街道研究来，见给研究员的那份稿子的第 6 个问题 |
| 远近 | 近处骨骼动画，中景顶点动画，远处不画 |

身体和衣服的建模交给 Opus 会话或者我。动作重定向和顶点动画烘焙是编辑器脚本，Sonnet 可以写。

### U4 阅读和故事，四周

- 界面用 UI Toolkit。中文字体用思源宋体或 Noto Serif SC，都是开放授权，动态字库。
- 状态切换：每个状态一份图层开关表，按块加载。
- 段落触发接到镜头运动（Cinemachine）。
- 存档：读到哪、状态、设置。Steam 云存档可以不写代码，按文件自动同步。
- 中英文用 Unity 的本地化包。

### U5 地面视角的美术，只做竖切片的街区，六到八周

按 U0 列出的缺项清单做：门和门槛、店面和柜台、路面石块和车辙、路边水池和神龛、招牌和告示。全部建模，给 Opus 会话。民居专员分支上的 15 种新民居和店面是现成的起点，所以那个分支要先合并。

### U6 Steam，四周，可以和 U4、U5 并行

| 事 | 说明 |
|---|---|
| 入驻 | 每个应用交 100 美元，卖到 1000 美元后返还。身份、税务、银行资料的审核要 15 到 30 天 |
| 等待期 | 交费后 21 天才能发售 |
| 商店页 | 发售前至少公开"即将推出"两周。商店页和游戏包各要审一次，每次 1 到 5 天 |
| 接口 | 成就（读完的卷、找到的地点）、云存档、手柄 |
| Steam Deck | 要支持机身按键；1280×800 下最小字高不低于 9 像素。阅读器的字要专门调 |
| 试玩 | 做一个试玩版赶一次新品节，是独立游戏最主要的曝光 |
| 宣传片 | 视频组已有分镜和工具 |

### U7 发售前的三件非技术的事

**AI 内容申报。** Steam 的内容调查有生成式 AI 一栏。随游戏发行的、用 AI 工具做的内容都要申报，代码和模型都算。这个项目几乎全部都是，照实写。

**成人内容申报。** 调查要求申报玩家可能遇到的全部成人内容，包括包里有但走不到的。小说里的感情线按实际内容填。

**授权清点。** 现在 `NOTICE.md` 只有 4 条。发售前要逐项落实：

| 东西 | 问题 | 怎么办 |
|---|---|---|
| 八音盒卡农的音频 | 曲子是公版，这份录音的来源没有记录 | 找到来源，或者重新录、重新合成 |
| GPT、Kimi 做的模型 | 仓库里没有授权说明 | 查各家条款对商用产出的规定，记进 NOTICE |
| `data/empire.json` | 来自 AWMC，ODbL 授权，要署名并保持同样授权 | 这个文件继续公开，游戏里署名 |
| 参考图 | 有 CC BY-SA 的预览图和游戏截图 | 只当参考，不进游戏包。确认没有哪个资产是照着描的 |
| 字体 | NOTICE 没登记 | 补上 |
| Unity | 个人版：过去 12 个月收入和融资低于 20 万美元可用；Unity 6 的启动画面可以关；没有按安装量收的费用 | 无需处理 |

还有一件要你自己问清楚：以个人身份在 Steam 上有收入，对你的税务和居留身份有没有影响。

## 4. 机器和工具

- Unity 6 的编辑器能在你的 Mac 上跑。Windows 版可以从 Mac 上打包（Mono 后端）。
- 但玩家大多用 Windows 和独立显卡。需要一台 Windows 机器实测，或者用 GitHub Actions 自动打包，再借机器测。Steam Deck 也要实测一次。
- agent 操作 Unity 最稳的方式是命令行：编辑器的批处理模式运行编辑器脚本，自动化测试，脚本出截图。和现在"任务书、构建、看图"的流程一样。场景文件不要让 agent 手改，一律用脚本生成。

## 5. 时间和先后

各阶段加起来是七八个月的量，一个人带几个 agent 做。能并行的是 U4、U5、U6。

1. 现在：不动 Unity。先做项目计划里的第 0、1 阶段。v2 没成为默认、民居分支没合并之前导出，等于导出一座马上要变的城。
2. 12 月：构件登记表和稳定编号；网页里试一条能走的街，拿到缺项清单。
3. 2027 年 1 月：U0 试验，决定走不走。
4. 2 月到 4 月：U1、U2，竖切片。
5. 5 月到 7 月：U3、U4、U5，商店页上线，试玩版。
6. 之后：发售。

状态拆成 9 个还是 11 个，要在导出之前定。

## 6. 这到底是个什么游戏

这一条比技术更需要你来定，定了才知道竖切片做什么。现在它是一个带城市的阅读器。上 Steam 至少要说清玩家做什么。几种不互斥的可能：

- 读小说，城市跟着章节变。（已有）
- 在街上自由走，看人，听声音。（U3、U5）
- 找东西：铜牌、彩蛋、【史】的注释，攒成一本图鉴。（成就的来源）
- 拖时间轴，看同一条街在九个状态里的样子。（已有数据）
- 拍照模式。（便宜，对宣传有用）

声音现在几乎没有：只有八音盒和合成的铃声。走在街上需要环境声，这是一笔单独的预算。

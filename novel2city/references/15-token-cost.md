# 15 · Token 花在哪里：Haiku 建模 vs Sonnet 集成（罗马第 6 轮复盘）

数据来自《尼禄重工纪元》罗马沙盘第 6 轮（2026-10-22/23）：1 个 Opus 主管、1 个 Sonnet 集成工程师、约 25 个 Haiku
Blender 工人。每次子代理交回时系统给出"最终上下文长度"和"工具调用次数"。

**估算方法：** 每次调用模型都要把整段上下文读一遍（多数命中缓存，按缓存价计费）。所以一轮的输入量
≈ 调用次数 × 平均上下文。这里的平均上下文取本轮开始与结束长度的平均。
**局限：** 这是数量级估算，不是账单；输出 token 和图片 token 没有单列。

## 1. 结果

| 工人 | 轮数 | 结束时上下文 | 调用次数 | 估算读入 |
|---|---|---|---|---|
| 过渡宫（Haiku，续用） | 4 | 517k | 167 | ≈ 70M |
| 看台 + 两端转角楼（Haiku，续用） | 4 | 545k | 150 | ≈ 70M |
| 梵蒂冈 + 静室（Haiku，续用） | 3 | 419k | 191 | ≈ 66M |
| 大母神庙 + 岩石工具（Haiku，续用） | 5 | 579k | 136 | ≈ 59M |
| 提比略宫（Haiku，续用） | 3 | 575k | 108 | ≈ 51M |
| AO 烘焙（Haiku，新开） | 2 | 467k | 130 | ≈ 37M（结论：不采用） |
| 岩石露头（Haiku，新开） | 3 | 209k | 144 | ≈ 24M |
| 一次通过的资产（维斯塔、巴西利卡、跑马场等 8 件） | 1 | 190–460k | 12–22 | 各 ≈ 3–6M |
| **Haiku 合计（约 25 个）** | | | ≈ 1 900 | **≈ 530M** |
| **Sonnet 集成（6 段）** | | 510–754k | 326 | **≈ 180M** |

模型单价不同。若 Sonnet 每 token 约为 Haiku 的 3 倍（按发布价的大致比例，读者应以当期价目为准），
**两边的花费其实差不多**：Haiku 530 单位，Sonnet ≈ 540 单位。"Haiku 便宜"只在单价上成立。

## 2. 精细化建模，哪一步最烧 token
1. **续用老工人做小修改（最大的一项）。** 续用的 Haiku 带着前几轮的全部历史，起步就有 300–450k 上下文。
   于是"把天篷改成紫色"这种小修，每一次工具调用也要读一遍 40 万 token。
   - 皇家看台的小修：35 次调用 ≈ 15M。
   - 新开的岩石工人第一轮：27 次调用，上下文最大 129k，≈ 2.5M。
   - 同样的工作量，续用比新开贵约 5 倍。
2. **"渲染 → 看图 → 改"循环在含糊标准下反复。** 下面几件都在 3–5 轮之间：
   - 岩石工具改了 5 轮。
   - 静室、正门转角楼各 3–4 轮。
   - 岩石露头改了 3 轮。

   原因是验收标准只有"像参考图"。等主管把做法写成精确配方（岩石露头第 3 轮：低频大振幅噪声 + 4–6 刀平面切
   + 减面），或给出数字目标（台阶陡度、像素颜色），一轮就过。**轮数比单价更决定成本。**
3. **Sonnet 的集成本身就重。** 它要读很密的单行代码文件，每轮要启动无头浏览器截 10–20 张图，还要把图读进上下文。
   - 第一阶段：161 次调用、2 小时 10 分。
   - 后面几段：上下文都在 70 万以上，每次调用都很贵。
4. **试验性方向。** AO 烘焙花了约 37M，结论是不用：低多边形大面只在角点采样，效果小，文件还大 1.7 倍。
   这类试验应先在 1 个模型上量化，再决定批量。
5. **主管（Opus）的审图不是大头。** 拼图审查（4–6 张拼成一张）每张图只需 1–2k token。贵的是主管自己越来越长的对话上下文。

## 3. 会不会有偏差
* **Sonnet 的任务更难：** 它做跨文件的代码集成、地形与着色器，并要自查截图；Haiku 做单个资产。
  按"每 token"比较对 Sonnet 不公平，应按"每件验收通过的成果"比较：
  - Sonnet：一段平均交付 4–8 项功能，并附截图。
  - Haiku：中位数是 1 件资产需要 1.5–2 轮。
* **Haiku 的估算偏高：** 续用的工人把第 3–4 轮的历史也带进来了。如果每个资产都从新开工人做起，Haiku 的总量估计能降到一半以下。
* **Sonnet 的估算可能偏低：** 它读入的截图很多，图片 token 不在"上下文长度"里完全体现。

## 4. 下次怎么做（写进流程）
1. **修改轮一律新开工人。** 给 10 行交接：做什么、文件路径、上轮问题、验收数字。不续用上下文超过 30 万的工人。
2. **两轮不过就换配方。** 主管写出具体建模步骤（如岩石配方），或改成数字验收；不再说"再像参考一点"。
3. **验收用数字和拼图。** 尺寸、三角面预算、像素颜色、悬浮检测数值；审图用拼图。
4. **集成工程师按阶段重开。** 每阶段结束让它写 15 行交接，下一阶段新开一个 Sonnet 读交接，不让上下文涨到 70 万。
5. **试验先量化。** 在 1 个模型上测出收益（如 AO 均值变化、文件大小），值得再批量。
6. **共享工具的修改由一个工人做。** 例如 rk.py 的岩石函数，测完再让各资产重导出。改共享文件前要得到作者同意，见 [10-pitfalls](10-pitfalls.md)。

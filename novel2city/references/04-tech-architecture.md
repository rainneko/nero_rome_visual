# 04 · 技术骨架

## 1. 路线选择（先比较，再动手）

| 路线 | 画质 | 交互 | 成本 | 适合 |
|---|---|---|---|---|
| 实时程序化 3D（three.js） | 精致微缩沙盘 + 油画调色 | 可漫游、随章节变化 | 中 | **默认** |
| 固定机位白模 + AI 重绘 | 接近手绘插画 | 只有固定画面 | 低–中 | 英雄镜头、封面 |
| 预渲染精灵图（经典城建游戏做法） | 稳定 | 2.5D | 中 | 等轴测风格 |
| 高斯泼溅世界（World Labs Marble + Spark） | 照片感 | 可漫游 | 按世界计费 | 氛围场景；难以精确编辑史实布局 |
| 离线渲染（Blender/引擎） | 最高 | 视频或图片 | 高 | 宣传片 |

经验：
- 开源城建游戏里没有能直接做"网页 3D 古城"的项目；经典城建游戏的共同做法是"离线渲染的精灵图 + 数据驱动"。
- athenaion 的画质来自巨大的工程量和离线 4K 渲染，单个 HTML 复制不了；但它的**方法**（参考图驱动、全程序化、自动截图比较）可以学。
- 我们最终用实时程序化 3D 做全城，用 GLB 做少数核心建筑，固定机位重绘留作封面方案。

## 2. 世界组织
- 坐标：1 单位 = 1 米，原点 = 中心地标。子场景放在同一世界的远处（本案例：安齐奥在 (-70000, 0)，奥斯提亚在 (-70000, -80000)），用页面按钮淡入淡出切换。
- **合并几何**：同材质的三角形收集进一个缓冲区（本案例叫 GB），一组一个网格，绘制调用少。
- **着色器画细节**：窗户、屋瓦、砖纹、夜间灯光在着色器里画，不建几何。
- **实例化**：柱子、树、人群用实例化。
- **图层**：故事内容都放进命名图层（`L(name, s0, build)`），每个图层有状态区间。
- **状态**：`STATES[i]` 定义年份、标题、默认机位、天气、引语、图层；`setState(i)` 切换图层、标签、资源栏。
- **章节闸门**：阅读器知道当前章号，`applyGates()` 决定细粒度对象（例：青铜规矩柱第 7 章才出现；第 3 章的祭典看台）。
- **段落触发**：`TRIG` 里写一句原文；这句到达阅读线时，镜头飞到指定机位，事件标志改变（例：第 3 章战神广场热气球 → 大竞技场热气球）。

## 3. 构建与仓库
```
src/shell.html                页面骨架和样式，构建时注入脚本
src/core/                     渲染器、天空、天气、季节、昼夜、后期；材质与几何构建器
src/world/                    建造工具（神庙、圆庙、院落、柱廊、喷泉）、地形与道路、地块与民居
src/scenes/<city>/            每个城市/子场景一个目录：地标、图层、地形……
src/ui/                       状态、资源栏、阅读器、地名链接、触发、页面、音乐、地图
data/                         密度图、地图数据
assets/models/*.glb           核心建筑；tools/models/ 放生成脚本
tools/build.mjs               按顺序拼接、内联数据和 GLB，输出一个自包含 HTML
tools/test/                   启动测试、固定机位截图
briefs/                       核心资产任务书；.claude/agents/ 放建模子代理
.github/workflows/pages.yml   推送即部署
```
- 经典脚本拼接时，顶层常量是全局的：**加载时就执行的代码要排在它用到的常量后面**（本案例一次页面起不来，就是一个列表在常量定义之前读取了它）。
- 拆仓库时做一次逐字节比对：新构建和旧单文件必须完全相同。

## 4. 测试
- 页面暴露 `window.__shot(state, view, tod)` 返回截图；测试模式关掉阴影和油画滤镜（软件渲染跑不动）。
- 启动测试：等 `__ready`，收集页面错误，打印资源栏。
- 几何检查：扫描图层里的 NaN 顶点。
- 区域探针：列出某个区域里所有实例化柱子的位置、颜色、高度，用来找"是哪段代码放的"（见 `scripts/probe_instances.js`）。

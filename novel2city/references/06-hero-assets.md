# 06 · 核心资产：从参考图到网页里的 GLB

## 1. 什么算核心资产
读者会盯着看、书里反复出现、形制独特的建筑：本案例的朱庇特神庙、元老院、提比略宫，以及安齐奥的观测塔、窄桥、孤岩侧殿、行宫主殿。
其他交给程序化生成。

## 2. 朱庇特神庙为什么成功
1. **参考图对**：正面复原图能看清山花、台阶、屋顶；时代对得上。
2. **史料交叉核对**：正面六柱、三间内殿、深台基；正中大台阶夹在两侧挡墙之间（约 17 米宽）。
3. **细节逐项过**：山花里的群像、青铜大门、陶瓦屋顶——并且发现过一次**盖瓦方向做反**，改成从檐口铺向屋脊。
4. **单独成文件**：一个生成脚本 + 一个 GLB，便于反复修改。
5. **放置绑定变量**：位置绑定卡比托利欧平台高度，平台改了神庙跟着改。

## 3. 任务书（每个资产一份，模板见 `templates/asset-brief.md`）
书中原文（逐字）· 史料要点 · 形状与尺寸 · 材质调色板 · 必须有 · 不许有 · 三角面预算 · 四个固定预览机位（正面、侧面、四分之三俯视、顶视）· 验收清单。
例：窄桥——"只容两人并行，**两侧没有栏杆**，桥头铁门，日耳曼卫兵轮班"。作者给的参考图里有栏杆，最后按书。

## 4. 主控 + 工人循环（Claude Code + Blender MCP）
1. 主控（Opus）把任务书交给工人子代理（`model: haiku`，定义放 `.claude/agents/`，一次一个资产）。
2. 工人在 Blender 里建模，渲染四机位到 `renders/<asset>/`，导出 `assets/models/<asset>.glb`，报告三角面数和没做到的项。
3. 主控把渲染图和任务书、参考图、史料对照，回一份**编号的修改清单**（只写要改什么，不写"再好一点"）。
4. 重复到清单全部打勾。然后放进场景，在场景机位里再查一次比例、朝向、和地形的衔接。
- 注意：子代理是 Claude Code 的功能；Blender MCP 要在 Claude Code（或 Claude Desktop 的新对话）里接好，工具列表里能看到才算接通。

## 5. 进网页
- 规格：米制、Y 轴向上、原点在占地中心的地面；单个资产约 4 万三角面以内；材质名对上调色板。
- 加载：GLTFLoader；单文件交付时把 GLB 以 base64 内联；加载失败时退回程序化版本。
- 托管到仓库时可以考虑 Draco/meshopt 压缩；重复构件用实例化。
- 水面、瀑布用半透明面片加滚动贴图，不要用流体模拟（导出文件会大到网页带不动）。

## 6. 不用 MCP：Blender 后台模式 + 积木库（安齐奥实测）
Blender MCP 一次只连一个场景，几个工人同时改会互相覆盖。改用**后台模式**：每个工人写一个 Python 脚本，
`Blender -b --factory-startup -P 脚本.py` 一次跑完建模、出图、导出（几秒钟），脚本本身就是可复现的源文件，可以并行。

**给 Haiku 一个积木库**（安齐奥用的是 `tools/models/antium/bl_kit.py`），把容易错的东西封装好：
- 立面"外皮开洞 + 洞口侧壁 + 深色内板"——窗洞真的凹进去，永远不会看穿，也不会是纯黑；
- 双坡顶自带封闭山墙三角、四坡顶自带瓦垄和檐下封板——历史上"缺三角""瓦片方向反"的坑直接消失；
- 柱式、柱廊、环形柱廊、拱廊、台阶（每级实心落地）、栏杆、雕像、水池、花坛、整栋楼、四合院、方塔；
- `finish()`：按材质合并成一个物体、报三角面数、四个机位按包围盒自动取景出图、导出 Y 轴向上的 GLB。

**主控审图时反复出现的问题**（写进任务书的"不许有"更省事）：
- 斜坡塔脚外撇太大、颜色太浅，远看像两块沙色坡道 → 外撇 ≤0.4 米，颜色接近岩石；
- 每层一道红腰线 → 像条纹灯塔，只留顶部一道；
- 中庭/院子一大片白色铺地 → 要求草坪四分区 + 碎石十字路 + 水池雕像；
- 檐梁从单坡屋面里穿出来、瓦垄在墙后伸出"梳齿" → 屋檐必须压在檐部之上；
- 基座做成巨大的黑盒子浮在海里 → 基座只比建筑大一圈，颜色用深灰岩石色。

**进网页前压缩**：`gltf-transform quantize --quantize-normal 8 --quantize-position 14`，体积约降到 57%，
three.js r147 原生能读（KHR_mesh_quantization）；再交给 GitHub Pages 的 gzip，12 个资产总共约 1.2 MB 传输。
子页面的模型单独打包成一个按需加载的脚本（打开该页面才下载），首页不变慢。每处放置都先画一个程序化替身，模型加载失败时替身留着。

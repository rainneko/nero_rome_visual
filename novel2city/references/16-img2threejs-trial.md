# 16 · 试用 img2threejs：和 Blender 流程对比（2026-10-23）

[img2threejs](https://github.com/img2threejs/img2threejs) v2.0：从一张参考图出发，用纯 three.js 代码（TypeScript 工厂函数）重建物体，
由约 90 个 Python 脚本把关：图像分析 → 规格 → 严格校验 → 分 8 个阶段生成（blockout → structural → … → optimization），
每个阶段都看一张"参考图 | 渲染图"对比图。强项是单个道具、武器和角色（骨骼、蒙皮、头发）；建筑、街道、城市在路线图上
（v2.2、v3.0），目前没有。

## 同题对比：圆亭泉亭（`briefs/rome/tholos_fountain.md`）
同一份简报、同一张参考图（街景截图里裁出的一小块）、同一个模型（Haiku）、都是新开工人。

| | A：我们的 Blender 流程 | B：img2threejs（generic 配置） |
|---|---|---|
| 结果 | 完整模型，清单全部通过 | 只做到第 1 阶段 blockout（八边形拱廊 + 屋顶）；泉、天窗、陶罐、水都没做 |
| 审图轮数 | 1 | 2（第 2 轮门槛判"要求更多输入"，卡住） |
| Token / 工具调用 / 时间 | ≈ 140k / 18 / 5 分钟 | ≈ 371k / 143 / 27 分钟 |
| 三角面 / 文件 | 2 856 / 117 KB | 1 032（不完整）/ 去贴图 795 KB；带贴图导出 78 MB（userData 塞进 JSON） |
| 外观 | 浅色石材、红瓦锥形屋顶（应更像穹顶） | 程序化贴图噪点重，屋顶成了光滑浅色穹顶（不是红瓦），拱比较清楚 |
| 接入项目 | 直接放进 `assets/models/rome/`，名字映射材质 | 要去 TypeScript、改成经典脚本，或另写导出 GLB；材质名对不上 |

**B 卡住的原因（工人报告，均可复现）：**
* 剪影门槛（silhouette IoU）只能用于单物体照片；街景裁图前景占比低，必然不过。
* 转台门槛把拱门洞当成"破洞"。
* 本机 Python 3.9，工具要 3.10。
* 材质库没有"无釉陶瓦"，屋顶被给了釉面。
* 分阶段生成：完整模型要过 8 个审过的阶段，超过轮数上限。

## 结论
* **不替换现有流程。** 对建筑和城市，Blender（bevel、布尔、减面、岩石配方、kit 复用）更快、更便宜、出图更完整。
  img2threejs 的门槛是为单个物体照片设计的，用在街景参考图上反而成了阻碍。
* **值得借鉴（已在我们流程里或计划加入）：**
  1. 每阶段改正轮数有上限（3/阶段，6/总），超了回去改规格 —— 与 [15-token-cost](15-token-cost.md) "两轮不过换配方"一致。
  2. 先查几何再渲染：在 Blender 里先跑"悬空/未连接部件"检查，再出图交审。
  3. 动手前列"细节清单"，每个细节对应一个部件或材质。
  4. 审图用一张"参考图 | 渲染图"并排对比图。
  5. 颜色从参考像素里取（神殿降白已用像素探针）。
* 照片投影贴图（它的主推手段）不适合：我们的参考多是游戏截图，投影像素等于搬运别人的美术。
